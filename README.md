# 쇼핑 (spring-shopping-precourse)

온라인 쇼핑몰의 상품·회원·위시 리스트 HTTP API를 스프링 부트로 구현한다. 요청과 응답은 JSON으로 주고받는다.

## 기능 목록

### 1. 상품
- [ ] 상품을 생성한다 (이름, 가격, 이미지 URL) → 201
- [ ] 상품 하나를 조회한다 → 200, 없으면 404
- [ ] 상품 목록을 조회한다 → 200
- [ ] 상품을 수정한다 → 200, 없으면 404
- [ ] 상품을 삭제한다 → 204, 없으면 404

### 2. 상품 유효성 검사 (실패 시 400)
- [ ] 이름은 비어 있을 수 없고, 공백 포함 최대 15자다
- [ ] 이름에는 ( ) [ ] + - & / _ 외의 특수 문자를 쓸 수 없다
- [ ] 이름에 비속어가 있으면 안 된다 (PurgoMalum API로 검사)
- [ ] 가격은 0 이상이어야 한다
- [ ] 이미지 URL은 http:// 또는 https://로 시작해야 한다

### 3. 회원
- [ ] 이메일과 비밀번호로 가입하고 토큰을 받는다 → 201
- [ ] 이메일 형식이 틀리거나, 비밀번호가 비어 있거나, 이미 가입된 이메일이면 400
- [ ] 로그인에 성공하면 토큰을 받는다 → 200
- [ ] 이메일이나 비밀번호가 틀리면 401
- [ ] 비밀번호는 원문이 아닌 해시값으로 저장한다

### 4. 인증
- [ ] `Authorization: Bearer {토큰}` 헤더로 로그인한 회원을 찾는다
- [ ] 헤더가 없거나 토큰이 틀리면 401

### 5. 위시 리스트 (로그인 필요)
- [ ] 위시 리스트에 상품을 추가한다 → 201, 없는 상품이면 404
- [ ] 이미 담은 상품을 다시 담으면 400
- [ ] 내 위시 리스트를 조회한다 → 200
- [ ] 위시를 삭제한다 → 204, 없으면 404, 다른 회원의 위시면 403

### 6. 오류 응답
- [ ] 모든 오류는 같은 형식으로 응답한다: `{ "message": "오류 내용" }`
- [ ] 비속어 검사 API에 연결할 수 없으면 503

## 구현 전략

### 구조
- 기능별 패키지: `product`, `member`, `wish`, `common`
- 계층: Controller(요청·응답) → Service(흐름·트랜잭션) → 도메인(검증 규칙) → Repository(JPA)
- 검증 규칙은 도메인 객체(`ProductName` 등)에 두어 스프링 없이 단위 테스트할 수 있게 한다

### 데이터
- DB는 H2 인메모리, 테이블은 Flyway 마이그레이션으로 만든다 (V1 상품, V2 회원, V3 위시)
- 상품을 삭제하면 그 상품이 담긴 위시도 함께 삭제한다

### 인증
- 로그인할 때마다 UUID 토큰을 새로 발급해 회원 테이블에 저장한다
- 컨트롤러에서는 `@LoginMember` 파라미터로 로그인한 회원을 받는다 (ArgumentResolver)

### 외부 API
- 비속어 검사는 `ProfanityChecker` 인터페이스로 분리한다
- 실제로는 PurgoMalum을 호출하고, 테스트에서는 가짜 구현을 써서 외부 API 상태와 상관없이 테스트가 통과하게 한다

### 테스트
- 도메인 규칙: JUnit5 + AssertJ 단위 테스트 (`@ParameterizedTest`로 경계값 검사)
- API: `@SpringBootTest` + MockMvc로 요청부터 응답 코드·본문까지 검사

### 프로그래밍 요구사항 지키는 법
- 들여쓰기 2단계 이하: 조건문 안의 로직은 메서드로 분리한다
- 메서드 15줄 이하, else·switch·3항 연산자 금지: `if`에서 바로 return하거나 throw한다

### 요구사항에 없어 직접 정한 것
- 상품 생성·수정·삭제는 인증 없이 허용한다 (관리자 개념이 요구사항에 없음)
- 가격 0원(무료 상품)을 허용한다
- 같은 상품을 위시에 중복으로 담을 수 없다
